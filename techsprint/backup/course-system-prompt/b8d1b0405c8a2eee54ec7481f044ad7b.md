Materi disusun dengan pendekatan tingkat dasar sesuai kebutuhan workshop, sehingga alur belajar berfokus pada pemahaman konsep dan praktik konfigurasi melalui antarmuka Winbox untuk menghasilkan jaringan yang berfungsi.

Materi course ini membahas pondasi jaringan dan praktik dasar menggunakan Mikrotik RouterOS. Pada bagian pengantar, modul menegaskan tujuan workshop: meningkatkan pemahaman peserta terhadap penggunaan teknologi jaringan khususnya Mikrotik agar peserta mampu memiliki kemampuan profesional untuk terjun ke dunia kerja. Tingkat kesulitan pelatihan ditargetkan pada level dasar, sehingga output yang diharapkan setelah mengikuti workshop adalah peserta mampu membuat router Mikrotik dan melakukan administrasi jaringan sederhana.

Untuk networking fundamental, modul menjelaskan bahwa jaringan komputer menghubungkan banyak komputer agar dapat berkomunikasi. Komunikasi diwujudkan melalui pertukaran data dari pengirim ke penerima. Agar data dapat sampai ke pihak yang tepat, pengiriman pesan memerlukan alamat, yaitu IP Address. IP Address yang paling umum dipakai adalah IPv4. IPv4 terdiri dari 4 byte (masing-masing byte dipisahkan dengan titik) dan nilai tiap byte maksimum 255, sehingga secara konseptual jumlah kemungkinan alamat sangat besar. Modul juga menekankan struktur IP Address yang terdiri dari dua komponen: network address dan host identifier. Network address menentukan jaringan mana yang dimaksud, sedangkan host identifier menentukan perangkat/host yang berada di dalam jaringan tersebut.

Dari struktur tersebut muncul aturan komunikasi: bila host berada pada network address dan subnet mask yang sama, komunikasi dapat terjadi secara langsung antar host. Namun apabila host berada pada network address yang berbeda, komunikasi memerlukan router karena router menjadi perantara yang akan menentukan jalur menuju jaringan tujuan. Modul juga menyebutkan sejarah pengalamatan IPv4 berbasis class, namun saat ini metode class tidak relevan lagi karena perkembangan internet, sehingga digunakan CIDR (Classless Inter-Domain Routing). CIDR memakai notasi slash (/) diikuti angka desimal 0–24 yang menyatakan panjang subnet mask. Dengan notasi ini, subnet mask dapat diturunkan dan batas network-host menjadi lebih fleksibel. Contoh diberikan untuk menjelaskan makna /24, dimana /24 setara dengan subnet mask 255.255.255.0, sehingga network address ditentukan oleh oktet pertama sampai tiga (misalnya 192.168.100.14/24 memiliki network address 192.168.100.0). Modul turut memberikan ilustrasi lain tentang bagaimana suatu IP masuk atau tidak masuk ke subnet tertentu menggunakan contoh 10.10.1.44/27 dibanding 10.10.1.90.

Setelah pemahaman IP addressing, modul masuk ke subnetting. Subnetting muncul karena dalam praktik sering diperlukan lebih dari satu network yang dibangun dari sebuah alamat network. Proses memecah network menjadi beberapa network kecil disebut subnetting. Modul merangkum tujuan subnetting: efisiensi penggunaan IP address, mengurangi kepadatan traffic jaringan (karena jaringan dibagi lebih terstruktur), serta memudahkan pengelolaan. Untuk membentuk subnet saat ini modul menekankan VLSM (Variable Length Subnet Mask), yaitu metode pembentukan subnet yang dimulai dari pendefinisian jumlah host yang dibutuhkan pada tiap subnet. Setelah kebutuhan host ditentukan, barulah subnet mask yang sesuai dipilih agar setiap subnetwork terbentuk dengan ukuran yang tepat.

Bagian routing menjelaskan bahwa komunikasi lintas jaringan berbeda membutuhkan jalur. Routing adalah proses penentuan jalur, dan dilakukan pada router. Router memiliki fungsi menyediakan jalur menuju jaringan lain dengan menggunakan routing table. Routing table merupakan daftar rute/jalur yang dapat dilalui menuju network tertentu. Pengisian routing table bisa dilakukan secara static (manual) atau dinamis (menggunakan algoritma). Modul menyebutkan informasi yang dibutuhkan untuk mengisi routing table, yaitu alamat network tujuan, alamat router yang menangani jaringan tersebut (next-hop/tujuan), serta alamat router tetangga yang dapat dilalui untuk mencapai network tujuan. Routing table dibuat pada masing-masing router agar router dapat menentukan rute saat paket dikirim menuju network lain. Ilustrasi yang disampaikan memperlihatkan hubungan beberapa jaringan melalui router berdasarkan keputusan dari routing table.

Pada bagian Mikrotik RouterOS fundamental, modul mengawali dengan pengenalan Mikrotik OS dan fungsinya. Mikrotik RouterOS adalah sistem operasi khusus untuk memanajemen network. Kata Mikrotik berasal dari bahasa Latvia yang berarti network kecil, dan fokusnya adalah memudahkan manajemen networking melalui kemudahan implementasi, konfigurasi, serta integrasi dengan perangkat lain. Modul membedakan Mikrotik RouterOS dan Mikrotik RouterBOARD. RouterBOARD adalah hardware spesifik dengan Mikrotik OS tertanam, sedangkan RouterOS dapat diinstall pada PC sehingga PC bisa berfungsi sebagai router. RouterOS mendukung banyak fungsi seperti router, bridge, firewall, pengaturan bandwidth, wireless access point/client, dan lainnya. Untuk administrasi, Mikrotik menyediakan tool; tool yang umum adalah Winbox yang berbasis GUI pada sistem Windows.

Konfigurasi yang dipraktikkan meliputi IP static, DHCP Server, dan routing static. Untuk IP static, modul menjelaskan langkah menggunakan Winbox: membuka winbox.exe, menghubungkan dengan memasukkan IP Mikrotik pada kolom Connect To, memasukkan username dan password, lalu Connect. Setelah berhasil masuk, pengguna membuka menu IP kemudian memilih Addresses untuk konfigurasi IPv4. Pengguna menambahkan address dengan menekan tombol +, lalu mengisi kolom Address (IP static dengan netmask), kolom Network bila diperlukan (kosong jika netmask sudah diisi di Address), dan memilih Interface yang digunakan. Setelah konfigurasi, menekan Apply dan OK sehingga IP muncul di Address List.

Selanjutnya DHCP Server. Modul menekankan bahwa DHCP Server memberikan IP otomatis kepada client yang diset ke mode automatic. DHCP Server menyuplai parameter penting: IP Address, IP Gateway, dan IP DNS Server. Konsep konfigurasi DHCP dibagi menjadi dua langkah utama: membuat IP Pool (range alamat yang diberikan ke client) dan membuat DHCP Server yang menggunakan pool tersebut, kemudian menambahkan DHCP Network yang menentukan network parameter yang akan dikirim ke client.

Langkah membuat IP Pool: di Winbox pilih IP lalu Pool, tambahkan pool baru dengan tombol +, isi Name dan Addresses (misalnya bentuk rentang seperti 172.16.162.30-172.16.162.40). Setelah Apply dan OK, pool muncul di daftar. Tahap berikutnya pembuatan DHCP Server: pilih IP lalu DHCP Server, tekan + untuk New DHCP Server, isi Name, pilih Interface (interface yang terhubung ke jaringan local), serta pilih Address Pool. Lalu Apply dan OK. Setelah DHCP Server dibuat, konfigurasi DHCP Network dilakukan pada tab Networks: tambah entri baru, isi Address (alamat network), Gateway, Netmask (prefix), dan DNS Server. Setelah testing, client yang meminta IP via DHCP seharusnya menerima parameter sesuai konfigurasi. Modul juga mengarahkan pengujian dengan ping dari client ke IP Mikrotik untuk memastikan konektivitas berjalan.

Terakhir, modul memperkenalkan routing static sebagai routing yang routing table-nya ditetapkan manual. Static routing merupakan pengaturan routing paling sederhana dan dapat digunakan untuk mengarahkan paket ke network berbeda. Walaupun bagian tahapan implementasinya terpotong pada cuplikan akhir yang diberikan, konsep inti yang harus dipahami tutor adalah bahwa static routing mengandalkan perintah/rule rute yang ditulis manual berdasarkan informasi network tujuan dan next-hop (router tetangga). Dengan demikian, course ini menutup rangkaian dari dasar pengalamatan (IP/CIDR/VLSM) sampai penerapan konfigurasi Mikrotik (IP static, DHCP server, dan ide static routing) untuk membentuk jaringan sederhana yang dapat berfungsi.
