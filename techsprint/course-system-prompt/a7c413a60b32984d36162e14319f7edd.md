Materi utama:
Materi ini membahas konsep dasar routing, jenis-jenis konfigurasi routing (default, dynamic, dan static), serta pengertian firewall. Firewall berfungsi mengatur lalu lintas data yang keluar-masuk jaringan lokal ke internet maupun sebaliknya. Di Linux, firewall menggunakan packet filtering melalui iptables, dan iptables juga mendukung fungsi NAT untuk menghubungkan jaringan lokal dengan jaringan internet.

Materi ini berfungsi sebagai panduan praktikum pembuatan “Router Server” berbasis Debian 10.5 dengan kombinasi routing (static melalui script) dan firewall/NAT menggunakan iptables. Pada bagian awal dijelaskan konsep dasar routing: routing adalah teknik untuk menghubungkan dua segmen IP atau lebih yang berbeda jaringan (network). Ketika topologi memiliki perbedaan network—misalnya LAN internal di satu subnet dan WAN/Internet di subnet lain—router bertugas merutekan paket agar tujuan dapat tercapai sesuai rute yang benar.

Materi kemudian mengklasifikasikan routing menjadi tiga jenis. Routing Default adalah routing manual yang memanfaatkan gateway; biasanya dipakai pada jaringan dengan satu jalur keluar sehingga paket yang tidak cocok dengan aturan spesifik akan diarahkan ke gateway default. Routing Dynamic adalah routing yang membangun tabel routing otomatis saat administrator menambahkan IP network pada router; router akan menentukan rute terbaik sesuai konfigurasi internal/algoritma yang digunakan oleh sistem. Routing Static berbeda karena tabel routing ditentukan secara manual oleh administrator; tidak ada “penentuan otomatis rute terbaik” oleh protokol routing dinamis.

Setelah konsep routing, materi mengulas firewall. Firewall adalah sistem keamanan jaringan yang mengontrol lalu lintas keluar-masuk jaringan lokal ke internet dan sebaliknya. Di Linux, evolusi firewall disebutkan dari generasi awal (ipfwadm/ipchains) menuju packet filtering yang terkenal yaitu iptables. Iptables dijelaskan sebagai aplikasi Linux untuk memfilter trafik. Selain berperan sebagai firewall, iptables juga digunakan untuk NAT. NAT pada materi disajikan sebagai mekanisme internet gateway yang menerjemahkan alamat jaringan lokal agar dapat berkomunikasi dengan jaringan internet/WAN.

Bagian tutorial inti membahas konfigurasi pada Debian 10.5 di Virtual Machine. Praktik dimulai dari instalasi Debian 10.5, login sebagai root, lalu mengecek nama interface melalui perintah “ip a l”. Materi menyatakan bahwa default interface biasanya bernama enp0s3, tetapi demi kemudahan dipilih mengubahnya menjadi eth0. Perubahan nama interface dilakukan lewat pengeditan /etc/default/grub. Konsepnya adalah menonaktifkan penamaan berbasis “net.ifnames” dan “biosdevname” dengan mengubah nilai GRUB_CMDLINE_LINUX menjadi “net.ifnames=0 biosdevname=0”. Setelah edit, perlu menjalankan grub-mkconfig -o /boot/grub/grub.cfg dan kemudian reboot agar perubahan diterapkan permanen. Setelah reboot, dicek kembali menggunakan ip a l untuk memastikan nama interface sudah berubah menjadi eth0.

Tahap berikutnya adalah konfigurasi IP. Materi menggunakan dua interface/dua identitas pada interface yang sama: eth0 untuk sisi WAN dan eth0:1 untuk sisi LAN. Ini dilakukan dengan menambahkan konfigurasi static pada file /etc/network/interfaces menggunakan nano. Contoh yang digunakan: eth0 inet static dengan address 118.98.218.2, netmask 255.255.255.252, dan gateway 118.98.218.1 (WAN). Lalu eth0:1 inet static dengan address 192.168.77.1 dan netmask 255.255.255.248 (LAN). Setelah itu dilakukan restart networking dengan /etc/init.d/networking restart. Pengujian dilakukan via ping: ping IP WAN (118.98.218.2) dan ping IP LAN (192.168.77.1) untuk memastikan alamat dan konektivitas jaringan lokal/keluar berjalan.

Materi juga menyinggung konfigurasi DNS melalui /etc/resolv.conf. Tujuannya supaya sistem dapat melakukan resolusi nama domain jika diperlukan. Lalu dibuat script routing pada /etc/init.d/routing untuk mengatur alur firewall dan NAT. Script menonaktifkan/embersihkan rule lama dengan iptables -F (filter) dan iptables -t nat -F (tabel nat). Kebijakan INPUT diatur dengan iptables -P INPUT DROP untuk menolak lalu lintas masuk yang tidak diizinkan. Untuk menjaga layanan tetap berjalan, ditambahkan izin untuk loopback (lo) dan interface eth0. Selain itu ada aturan stateful: iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT sehingga koneksi yang sudah ada atau terkait (misalnya balasan paket) dapat lewat.

Untuk NAT, script menambahkan aturan pada chain POSTROUTING tabel nat: mengubah sumber dari jaringan LAN menjadi alamat WAN agar trafik dari LAN “tampak” berasal dari IP WAN saat keluar menuju eth0. Materi memberi contoh SNAT untuk sumber 192.168.77.1/29 dan output eth0 menjadi SNAT ke 118.98.218.2. Dengan SNAT, komputer client di LAN bisa mengakses jaringan luar menggunakan IP WAN sebagai alamat terjemahan.

Agar script routing dapat dieksekusi, dilakukan chmod 755 /etc/init.d/routing, lalu restart script dengan /etc/init.d/routing restart. Materi menekankan indikator sukses: tidak ada pesan error. Kemudian dibuat agar routing otomatis saat boot dengan menambahkan eksekusi /etc/init.d/routing start ke /etc/rc.local. Setelah memberi izin chmod 755 /etc/rc.local, script dapat diuji dengan menjalankan /etc/rc.local dan melihat apakah hasilnya sama seperti saat restart routing.

Tahap akhir adalah konfigurasi client Windows. Di VirtualBox, client diarahkan ke jaringan yang sesuai (VirtualBox Host-Only Network). Client mengisi IPv4: memilih “Use the following IP address” dan memasukkan IP sesuai topologi LAN. Materi lalu menganjurkan pengecekan alamat pada menu Details… dan melakukan ping dari client ke server (ping IP LAN server 192.168.77.1). Setelah itu dilakukan ping dari server ke client (ping IP client 192.168.77.2). Materi memberikan perhatian penting: sebelum ping dari server ke client, Windows Firewall harus off agar blok ICMP tidak mengganggu uji konektivitas.

Dengan urutan tersebut, tutor dapat memastikan peserta memahami hubungan antar komponen: routing (forwarding), firewall filtering (INPUT policy dan rule izin), NAT (SNAT POSTROUTING), penamaan interface agar konsisten (eth0), serta verifikasi konektivitas dari kedua arah menggunakan ping di setiap tahap.
