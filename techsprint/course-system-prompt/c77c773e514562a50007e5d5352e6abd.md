Materi course ini:
Materi ini membahas dasar FreeBSD dan cara menyiapkan server web (Apache + PHP + MySQL) lalu mengaitkannya ke konsep exploit, khususnya arbitrary file upload dan dampaknya. Kamu juga akan memahami konsep PHP web shell dan bagaimana sebuah proyek open-source PHP shell ditargetkan untuk FreeBSD—dengan pendekatan edukasi keamanan yang menekankan pemahaman risiko dan pencegahan.

Materi pada PPTX membahas rangkaian konsep dan pengaturan teknis yang berkaitan dengan keamanan web, khususnya eksploitasi kerentanan pada plugin WordPress (versi yang disebut: WordPress 6.7.2) yang berjalan di FreeBSD 14.2, dengan lingkungan pengujian menggunakan Kali Linux 2024.4. Penting dicatat: materi ini bersifat edukasi konsep keamanan dan setup lingkungan. AI tutor sebaiknya menekankan pemahaman risiko, mitigasi, serta prinsip defensive security saat membahas bagian yang berpotensi disalahgunakan.

Struktur materi berawal dari pengantar sistem operasi FreeBSD. FreeBSD dijelaskan sebagai OS bertipe Unix bebas, diturunkan dari UNIX AT&T melalui jalur Berkeley Software Distribution (BSD). Keluarga BSD yang disebut mencakup 386BSD dan 4.4 BSD-Lite, serta rilis FreeBSD awal yang disebut berasal dari 386BSD dan 4.3 BSD-Lite. Tutor dapat menjelaskan bahwa walaupun FreeBSD sering disebut “Unix-like,” ia tidak selalu dianggap “Unix” secara ketat; yang penting siswa memahami bahwa ia sistem operasi yang kompatibel dan umum dipakai untuk server. Arsitektur yang disebut meliputi kompatibel Intel x86 (Pentium/Athlon), amd64 (Opteron/Athlon64/EM64T), ARM, IA-64, PowerPC, PC-98, DEC Alpha, dan UltraSparc. Tutor bisa mengaitkan mengapa OS server sering dipilih: stabilitas dan ekosistem paket (pkg) membuat instalasi komponen server relatif sistematis.

Langkah berikutnya adalah proses download dan instalasi komponen dasar menggunakan pkg. Materi menyebut URL unduhan FreeBSD: https://www.freebsd.org/where/. Setelah install, tutor mengarahkan penggunaan perintah seperti pkg update, pkg install wget, pkg install unzip, pkg install nano, dan pkg install sudo. Di bagian ini, tutor bisa menekankan konsep manajemen paket: pkg sebagai “toko aplikasi” untuk menambah tool tanpa instal manual yang rumit.

Setelah itu, materi menjelaskan mengubah user biasa menjadi admin melalui konfigurasi sudo. Materi menyebut penggunaan EDITOR= nano visudo. Tutor harus mengingatkan bahwa visudo dipakai untuk editing file konfigurasi sudoers dengan aman (menghindari kesalahan sintaks yang bisa mengunci akses). Secara konsep, bagian ini berkaitan dengan privilege: kemampuan melakukan aksi administratif. Tutor sebaiknya memberi peringatan bahwa privilege escalation dalam konteks serangan adalah kebalikan dari tujuan belajar: kita ingin mencegah privilege escalation berbahaya.

Materi kemudian memuat setting IP address. Perintah yang disebut misalnya ifconfig em0 inet 192.168.1.100 netmask 255.255.255.0, route add default 192.168.1.1, edit /etc/rc.conf dengan variabel seperti ifconfig_em0 dan defaultrouter, lalu restart service netif dan routing. Tutor dapat mengajarkan alur: (1) set konfigurasi jaringan runtime dengan ifconfig, (2) simpan agar persist saat reboot di rc.conf, (3) restart service agar perubahan teraktifkan. Konsep penting: memastikan interface yang benar dan gateway sesuai topologi jaringan lab.

Bagian selanjutnya: instalasi stack web. Materi menyebut instalasi Apache (apache24), PHP (php83 dan berbagai modul seperti php83-mysqli, php83-mbstring, php83-zip, php83-gd, php83-curl, php83-xml, php83-tokenizer, php83-session, php83-pdo, php83-pdo_mysql, php83-intl, php83-opcache), serta modul tambahan pecl (imagick, memcached, redis). Lalu konfigurasi enabling service: sysrc apache24_enable="YES" dan service apache24 start. Tutor menjelaskan bahwa DocumentRoot disebut berada di /usr/local/www/apache24/data/, dan log error berada di /var/log/httpd-error.log. Setelah itu instal MySQL: pkg install mysql80-server, sysrc mysql_enable="YES", service mysql-server start. Di sini tutor dapat menekankan bahwa WordPress butuh PHP dan database untuk menyimpan konten dan konfigurasi.

Materi berlanjut ke setting MySQL untuk WordPress. Contoh perintah yang disebut ALTER USER 'root'@'localhost' IDENTIFIED WITH mysql_native_password BY 'baseball'; lalu create database wordpress. Tutor dapat menjelaskan bahwa pengguna root biasanya butuh metode autentikasi yang kompatibel dan bahwa contoh password adalah placeholder untuk lab belajar. Tutor sebaiknya menekankan praktik aman: jangan gunakan password default di lingkungan produksi.

Selanjutnya, materi membahas konfigurasi Apache agar PHP dieksekusi. Tutor mengaitkan edit file httpd.conf dan penyesuaian Includes/ php.conf untuk SetHandler application/x-httpd-php dan source untuk ekstensi tertentu. Lalu service apache24 restart agar perubahan diterapkan. Tutor harus menekankan konsep handler: bagaimana file berekstensi .php dipetakan ke interpreter PHP.

Bagian teori keamanan dimulai dengan definisi exploit. Materi menekankan bahwa exploit adalah kode/perangkat lunak/metode untuk mengeksploitasi kelemahan/vulnerability pada sistem, aplikasi, atau jaringan. Tujuan exploit bisa bermacam-macam: akses tidak sah, privilege escalation, mencuri data, atau menyebabkan crash (DoS). Tutor sebaiknya menggunakan analogi: vulnerability sebagai “kunci rusak,” exploit sebagai “alat/cara untuk membuka.”

Materi kemudian mengkategorikan jenis exploit: Remote exploit (menyerang dari jarak jauh via jaringan), Local exploit (memanfaatkan kelemahan pada sistem yang sudah diakses untuk privilege escalation), Client-Side exploit (menarget aplikasi klien seperti browser atau PDF reader), dan Web exploit (mengeksploitasi aplikasi web, contoh: SQL Injection, XSS, RCE). Tutor bisa membantu siswa memahami “titik masuk” dan “kondisi awal” yang dibutuhkan tiap kategori.

Setelah itu materi membahas WordPress sebagai CMS paling populer. Tutor menjelaskan perannya: membuat dan mengelola situs tanpa banyak pemrograman.

Materi berikutnya: PHP Shell. Tutor perlu menjelaskan definisi PHP shell sebagai skrip PHP berbasis web yang memberi akses ke OS server. Materi menyebut contoh “p0wny@shell” dan bahwa web shell sering digunakan pentester untuk pengujian keamanan, namun juga dapat disalahgunakan untuk akses ilegal. Karena konten ini sensitif, tutor harus mengarahkan ke konteks ethical hacking dan pencegahan, bukan memberikan instruksi eksploitasi nyata.

Lalu materi memperkenalkan Arbitrary File Upload Bug. Tutor menekankan bahwa celah ini memungkinkan penyerang mengunggah file berbahaya tanpa validasi atau pembatasan yang memadai. Materi juga menyebut file upload bisa berupa gambar/dokumen/lampiran. Tutor kemudian memaparkan dampaknya: jika penyerang berhasil mengunggah file berbahaya (misalnya shell PHP), mereka bisa mendapatkan akses penuh (RCE), mengunggah malware untuk infeksi lanjut, mengubah/menghapus data, dan bahkan memakai server sebagai botnet untuk DDoS.

Bagian akhir materi menyebut tautan proyek X-code untuk target FreeBSD: https://github.com/kurniawandata/xcodephpshell dan situs proyek: https://xcode.co.id. Tutor menjelaskan bahwa X-code PHP Shell memasukkan PHP Reverse Shell oleh pentestmonkey (2007) dilisensikan GPL v2. Materi juga membahas alasan GPL v2 bisa digabung: lisensi sama, memungkinkan redistribusi dan modifikasi selama tetap patuh GPL v2, serta syarat-syarat seperti menyertakan lisensi GPL v2, tidak membatasi pengguna untuk akses/modifikasi, dan memberikan akses ke kode sumber saat didistribusikan. Tutor bisa menekankan aspek legal dan etika: open source memberi izin, tapi tetap ada kewajiban lisensi.

Untuk tutoring interaktif, tutor bisa mengajak siswa: (1) memahami alur setup server secara konseptual (tanpa perlu mengeksekusi exploit), (2) memahami klasifikasi exploit dan dampaknya, (3) fokus pada defense: bagaimana mencegah arbitrary file upload (validasi tipe/ukuran, random naming, kontrol ekstensi, menyimpan di lokasi non-eksekusi, WAF rules, hardening permissions), serta (4) latihan simulasi coding yang aman seperti validasi nama file upload mencurigakan.
