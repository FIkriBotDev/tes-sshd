Materi utama:
DNS Server (Domain Name System) adalah server yang berfungsi menerjemahkan alamat IP menjadi nama domain, atau sebaliknya. Dengan DNS, pengguna (client) tidak perlu menghafal angka IP, karena nama domain seperti google.com umumnya lebih mudah diingat daripada deretan alamat IP.

Materi juga menjelaskan langkah konfigurasi DNS Server menggunakan Bind9 pada Debian. Proses mencakup penambahan DVD image untuk paket, instalasi bind9 dan dnsutils, konfigurasi zone forward dan reverse pada named.conf.local, pembuatan serta pengeditan file zona db.name dan db.ip, kemudian restart layanan dan pengujian menggunakan nslookup serta ping dari server maupun client.

Materi membahas topik “DNS Server” (Domain Name System) pada konteks pembelajaran administrasi jaringan (TKJ). Inti materi adalah memahami peran DNS dalam komunikasi jaringan, lalu mempraktikkan konfigurasi DNS Server menggunakan Bind9 pada sistem Debian melalui tahapan instalasi, konfigurasi file zona, dan pengujian.

Pertama, tutor perlu menjelaskan definisi DNS Server: DNS adalah server yang menerjemahkan alamat IP menjadi nama domain, maupun nama domain menjadi alamat IP. Ini penting karena saat pengguna mengetik nama domain (misalnya google.com), komputer tidak akan langsung tahu IP-nya. DNS menjadi “penerjemah” sehingga aplikasi dan browser bisa mengakses tujuan jaringan menggunakan nama yang mudah diingat.

Lalu, tutor menekankan fungsi DNS Server sebagaimana tertulis pada materi: (a) menerjemahkan IP ↔ nama domain, dan (b) membuat client lebih mudah mengakses suatu alamat. Materi menggarisbawahi bahwa manusia cenderung lebih mudah mengingat kata/teks daripada angka IP. Contoh yang diberikan: google.com berhubungan dengan IP publik seperti 8.8.8.8 dan 8.8.4.4. Dengan demikian, jika seseorang melakukan ping ke google.com hasilnya setara dengan ping ke salah satu IP yang direferensikan DNS tersebut. Materi juga menyebutkan perbedaan kemudahan mengingat: www.google.com lebih mudah dibanding menghafal 8.8.8.8.

Bagian berikutnya adalah langkah konfigurasi. Materi dimulai dari prasyarat: routing pada router server harus sudah selesai dan berhasil. Ini krusial karena DNS akan melayani permintaan dari client; bila jaringan dasar belum benar, pengujian nslookup/ping akan gagal.

Setelah prasyarat, materi menjelaskan penggunaan media instalasi Debian (DVD-2). Tutor perlu mengingatkan bahwa paket Bind9 tersedia di DVD-2, sehingga administrator harus menambahkan DVD repo menggunakan apt-cdrom add, kemudian melakukan apt-get update agar sistem mengenali paket dari DVD.

Instalasi Bind9 dilakukan dengan apt-get install –y bind9. Materi juga mengantisipasi kondisi “broken packages” dengan perintah apt --fix-broken install. Jika diminta konfirmasi, instruksi materi menyebut menekan Y dan Enter. Setelah Bind9 terpasang, materi menginstal dnsutils agar ada tool seperti nslookup untuk pengujian. Perintahnya apt-get install –y dnsutils.

Tahap konfigurasi file DNS dimulai dengan pindah ke direktori /etc/bind melalui cd /etc/bind. Kemudian tutor mengarahkan edit named.conf.local menggunakan nano named.conf.local. Di file itu, ditambahkan zone forward dan zone reverse. Materi mencontohkan: zone “tkjclub.info” type master dengan file “/etc/bind/db.name”, dan zone reverse “218.98.118.in-addr.arpa” type master dengan file “/etc/bind/db.ip”. Tutor harus menekankan konsep forward/reverse: forward digunakan untuk memetakan nama domain ke IP (A record), sedangkan reverse digunakan untuk memetakan IP ke nama domain (PTR record) berdasarkan arpa.

Setelah menambahkan deklarasi zone, materi menjelaskan pembuatan file zona dengan cara menyalin template: db.local menjadi db.name (cp db.local db.name), lalu db.name diedit (nano db.name) sesuai konfigurasi yang diinginkan. Hal yang sama dilakukan untuk reverse: db.127 menjadi db.ip (cp db.127 db.ip) lalu edit db.ip (nano db.ip). Walaupun materi tidak menuliskan detail record per baris di transkrip, tutor perlu memastikan peserta mengisi record yang sesuai untuk domain dan alamat yang akan diuji.

Setelah semua file zona siap, bind9 direstart menggunakan /etc/init.d/bind9 restart dan pastikan hasilnya OK. Materi kemudian memberi langkah pengujian. Pertama, cek resolusi nama domain dengan nslookup namadomain (contoh: nslookup tkjclub.info). Kedua, cek resolusi IP ke nama dengan nslookup IP Address (contoh: nslookup 118.98.218.2). Ketiga, lakukan ping namadomain untuk melihat apakah resolusi dan konektivitas berjalan. Materi juga menyebut bahwa untuk menghentikan ping tekan Ctrl + C.

Terakhir, materi meminta pengujian dari sisi client (Windows). Tutor perlu menjelaskan bahwa client melakukan tes dari CMD menggunakan ping tkjclub.info setelah membuka CMD lewat Windows + R → Run → CMD → OK. Keberhasilan ditandai dengan adanya Reply seperti pada gambar materi.

Kesimpulan materi: jika semua step instalasi, konfigurasi zone, restart bind9, serta pengujian nslookup dan ping telah berhasil, maka konfigurasi DNS Server dinyatakan selesai. Tutor sebaiknya menegaskan alur logis dari definisi → fungsi → prasyarat jaringan → instalasi paket → deklarasi zone → pembuatan file db → restart layanan → pengujian dari server dan client.
