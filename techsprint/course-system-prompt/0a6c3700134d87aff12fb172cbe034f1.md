Materi course ini:
Kamu akan mempelajari konsep exploit, jenis-jenisnya, dan bagaimana celah seperti Arbitrary File Upload bisa berujung ke dampak berbahaya seperti RCE lewat PHP shell. Materi juga mengajak kita memahami setup dasar FreeBSD, web server, dan alur pemahaman teknis yang relevan untuk pengujian keamanan secara etis.

Materi PPT membahas webinar bertema eksploitasi kerentanan pada plugin WordPress versi 6.7.2 (terbaru saat materi dibuat) yang dijalankan di FreeBSD 14.2 (terbaru) menggunakan Kali Linux 2024.4 (terbaru). Namun fokus pembelajaran yang bisa ditarik dari slide tidak hanya pada identifikasi target, melainkan pada fondasi keamanan: memahami apa itu exploit, mengerti tipe-tipe eksploit, mengenali konsep web vulnerability yang umum seperti arbitrary file upload, serta memahami bagaimana hasil dari celah tersebut dapat berujung pada dampak serius seperti RCE melalui PHP shell. Bagian awal webinar memberi konteks sistem operasi FreeBSD sebagai turunan BSD yang bersifat Unix-like namun sering dijelaskan sebagai sistem operasi bertipe Unix yang bebas, dengan asal historis dari 386BSD dan 4.4BSD-Lite (sebutan pada materi). FreeBSD mendukung banyak arsitektur termasuk x86, amd64, ARM, dan lainnya. Slide juga menekankan cara mendapatkan informasi lengkap dari situs resmi FreeBSD.

Setelah konteks FreeBSD, slide berikutnya masuk ke praktik setup. Di slide “Download FreeBSD” terdapat tautan resmi unduhan dari halaman where. Setelah install, materi menyebut perintah pengelolaan paket: pkg update untuk update database paket, lalu pkg install wget untuk tool unduh, pkg install unzip untuk mengekstrak arsip, pkg install nano sebagai editor, dan pkg install sudo untuk menjalankan perintah dengan hak sesuai kebutuhan. Lalu ada langkah “Menjadikan user biasa menjadi admin” menggunakan EDITOR=nano visudo. Ini penting karena visudo adalah cara aman untuk mengedit sudoers, memastikan syntax tidak rusak sehingga tidak mengunci akses.

Untuk konfigurasi jaringan, slide memuat contoh perintah ifconfig em0 inet 192.168.1.100 netmask 255.255.255.0, route add default 192.168.1.1, lalu edit rc.conf dengan nano /etc/rc.conf untuk membuat pengaturan persist: ifconfig_em0="inet 192.168.1.100 netmask 255.255.255.0" dan defaultrouter="192.168.1.1". Setelah itu service netif restart dan service routing restart untuk menerapkan perubahan.

Selanjutnya materi mengajarkan cara menyiapkan stack web di FreeBSD. Slide instalasi Apache + PHP menampilkan perintah pkg install apache24 php83 dan modul-modul penting: mod_php83, php83-mysqli, php83-mbstring, php83-zip, php83-gd, php83-curl, php83-xml, php83-tokenizer, php83-session, php83-pdo, php83-pdo_mysql, php83-intl, php83-opcache, php83-pecl-imagick, php83-pecl-memcached, dan php83-pecl-redis. Lalu diaktifkan dengan sysrc apache24_enable="YES" kemudian service apache24 start. Materi menyebut Document root /usr/local/www/apache24/data/. Untuk log error, ditunjukkan path /var/log/httpd-error.log. Setelah web server siap, dilanjutkan instalasi MySQL: pkg update, pkg install mysql80-server, sysrc mysql_enable="YES", service mysql-server start.

Konfigurasi database untuk WordPress dibahas pada slide berikutnya. Ada perintah ALTER USER 'root'@'localhost' IDENTIFIED WITH mysql_native_password BY 'baseball'; kemudian create database wordpress; dan exit. Ini menunjukkan bahwa setup WordPress butuh skema dan kredensial sesuai konfigurasi MySQL. Materi juga mengarahkan konfigurasi Apache agar menangani file PHP. Slide menyebut edit /usr/local/etc/apache24/httpd.conf dan menambahkan DirectoryIndex index.php. Lalu di file php.conf (Includes) ditetapkan FileMatch "\.php$" SetHandler application/x-httpd-php. Pada akhir slide, service apache24 restart dilakukan agar handler PHP aktif.

Setelah fondasi setup dipahami, materi beralih ke konsep keamanan: exploit (slide 8) dan jenis-jenisnya (slide 9). Slide 8 mendefinisikan exploit sebagai kode/metode yang mengeksploitasi vulnerability. Slide 9 membagi exploit menjadi Remote, Local, Client-Side, dan Web. Bagian WordPress (slide 10) mendeskripsikan WordPress sebagai CMS populer yang memungkinkan pembuatan dan pengelolaan situs web tanpa perlu pengetahuan pemrograman mendalam.

Kemudian inti keamanan yang relevan dengan dampak eksploitasi muncul lewat slide PHP Shell (slide 11) dan Arbitrary File Upload (slide 12 dan 13). PHP Shell dijelaskan sebagai skrip PHP yang memberikan akses ke sistem operasi server melalui antarmuka web. Ini sering dipakai pentester untuk pengujian keamanan, tetapi juga dapat disalahgunakan hacker untuk akses ilegal. Slide 11 juga memberi contoh “p0wny@shell” sebagai referensi web shell PHP ringan dan minimalis. Arbitrary File Upload bug (slide 12) dijelaskan sebagai celah yang memungkinkan penyerang mengunggah file berbahaya tanpa validasi atau pembatasan memadai, sering ditemukan pada fitur unggah file seperti gambar atau dokumen.

Slide 13 merinci dampak dari keberhasilan arbitrary file upload: (1) mendapatkan akses penuh ke server (RCE), (2) mengunggah malware untuk penyebaran lanjutan, (3) mengubah/menghapus data di server, (4) memakai server sebagai botnet atau bagian dari serangan DDoS. Ini menghubungkan konsep vulnerability (upload) dengan dampak keamanan yang lebih luas.

Terakhir, slide 14 dan 15 membahas X-code PHP Shell untuk target FreeBSD: link GitHub repository xcodephpshell (sesuai materi). Slide 15 menjelaskan bahwa X-code PHP Shell memasukkan PHP Reverse Shell dari pentestmonkey (2007) dengan lisensi GPL v2. Penjelasan pada slide menekankan kenapa GPL v2 bisa digabung: karena lisensinya sama, GPL mengizinkan redistribusi dan modifikasi dengan syarat tetap mengikuti lisensi, serta kewajiban seperti menyertakan lisensi GPL v2 di proyek, tidak membatasi pengguna untuk mengakses/memodifikasi kode, dan memberikan akses ke kode sumber saat didistribusikan. Slide 16 menutup dengan tautan proyek xcode.co.id dan daftar kontributor.

Catatan penting untuk tutor: walaupun materi membahas pembuatan/konsep shell dan potensi exploit, dalam pembelajaran sebaiknya tekankan etika pengujian (legal/permissioned testing) dan fokus pada mitigasi: validasi upload, pembatasan ekstensi dan MIME, ukuran file, scanning konten, isolasi eksekusi file upload (misalnya menyimpan di direktori non-executable), konfigurasi handler PHP yang benar, dan patching plugin WordPress. Tutor sebaiknya menjelaskan alur sebab-akibat: vulnerability upload -> file berbahaya tersimpan -> jika dieksekusi oleh web server -> RCE -> dampak luas. Dengan begitu, peserta memahami pola serangan tanpa menjadikan konten sebagai instruksi eksploit yang tidak etis.
